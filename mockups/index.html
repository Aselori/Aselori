Profile mockups

Each mockup is shown the way GitHub will show it: an SVG inside an image tag, so no scripts, no external files and no clicks inside it. Colors follow your system's light or dark setting. Stack and copy are drafts.

A. Terminal, rebuilt

Your current idea, fixed: boxes drawn as shapes so they line up with any font, light and dark themes, the prompt's branch name says you're open to internships, and learning sits in its own dashed box.

Good

  • Keeps your identity, Catppuccin and the GIF
  • Lowest risk, fastest to finish

Watch

  • Terminal profiles are common now
  • Says "Linux user" louder than "backend"

B. A request through your stack

The stack drawn as the system it builds. A request travels client to API to data and back; the AWS boundary is dashed because it's the part you're learning.

Good

  • Reads as backend at a glance
  • Each tool sits where it does its job
  • Native GitHub colors, feels at home

Watch

  • Diagrams shrink badly on phones
  • Less personality; the GIF has no natural place

D. Your profile answers a request

The profile is an HTTP response: headers say who you are, the body is your stack. Below it, an access log of visitors who "sent a request" by opening a prefilled issue.

Send a request

  1. A visitor clicks the link; GitHub opens a new issue titled GET /hello with a message field.
  2. A GitHub Action reads it, appends a line to the log, redraws the SVG and commits.
  3. The Action closes the issue with a 200 OK reply.

Good

  • Backend vocabulary is the design
  • The Action pipeline is interview material

Watch

  • Needs moderation (spam, rude messages)
  • An empty log looks sad; needs a good empty state

E. Status page

You as a service status page. Everything you can defend is quietly "operational"; the only color and motion is cloud, "in progress". An Action updates the last deploy time daily.

Good

  • Honest about learning, and it's the point of the joke
  • Shows exceptions, not everything; scans fast

Watch

  • The joke only lands with people who know status pages (your audience does)
  • Most text, least visual
